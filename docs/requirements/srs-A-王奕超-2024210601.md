# A 线需求分册（王奕超 2024210601）

> 本文件是「CodeReviewAI 需求规格说明书（整合版）」的 A 线分册。
> 编号前缀固定为 `FR-A-NN` / `NFR-A-NN` / `UC-A-NN`，从 01 起编，与其余四线不冲突。

## 一、引言

### 1.1 目的

本分册定义 A 线（源码解析、`DiffUnit`、改动块切分）的需求边界，供整合版 SRS 汇总与实验三设计追溯。

A 线是整条审查链路的入口：把"一堆文件"或"一次 diff"变成规则引擎能直接消费的结构化块。**下游 B、C、D 三线的所有数字，都建立在 A 线切块是否准确之上**——切错一块，后面统计全错。

### 1.2 范围

**在范围内**：

- 目录遍历与文件筛选（含 `.gitignore`、二进制、大文件）
- 语言识别与编码识别
- unified diff 解析与改动块切分
- 行号映射（新文件坐标，从 1 起）
- `DiffUnit` 结构定义与产出
- 单文件失败时的降级与原因上报

**不在范围内**：

- 语法树与语义分析（本阶段只做行级切块，不做 AST）
- 规则判定与分级（B 线）
- 报告装配与接口（C 线）
- 持久化与统计（D 线）

### 1.3 术语

| 术语 | 含义 |
|---|---|
| `DiffUnit` | 解析产出的一块代码：文件路径、起止行、文本、语言、是否注释/空行 |
| hunk | unified diff 中以 `@@` 开头的段，标明旧/新文件的起止行与上下文 |
| 改动块 | 一个 hunk 在新文件中对应的连续行区间 |
| 跳过的文件 | 因二进制、超大、编码不可解等原因未解析的文件，必须带原因 |

## 二、总体描述

### 2.1 本线在产品中的位置

A 线上游接收：**用户给的路径或 `--diff <ref>`**；下游交付：**`DiffUnit` 列表（给 B 线规则引擎）**。

```
路径 / diff  ──→  [A 线：扫描 · 识别 · 切块]  ──→  DiffUnit[]  ──→  B 线规则判定
```

### 2.2 约束

- `DiffUnit` 字段一经冻结，B/C 线不得自行增删；需要加字段走变更流程
- 行号一律用**新文件坐标**，从 1 起（与报告 `Finding.line_start` 对齐）
- 解析过程只读，任何情况下不得修改被审代码
- 单文件失败不得中断整体审查（否则一个坏文件毁掉整次报告）

## 三、功能需求

| 编号 | 需求 | 描述 | 优先级 | 验收判据 |
|:----:|------|------|:------:|---------|
| FR-A-01 | 目录递归扫描 | 给定目录，递归列出所有可解析文件，默认遵守 `.gitignore` | M | 给 200 文件的目录，文件清单与 `git ls-files` 一致（差异 0） |
| FR-A-02 | 语言识别 | 按扩展名映射语言标识（py/js/ts/tsx 起步），未知后缀直接跳过并记原因 | M | `.py` → `py`，`.vue` → 跳过且原因为 `unsupported_lang` |
| FR-A-03 | 编码识别 | 支持 UTF-8、UTF-8-BOM、GBK；非法字节用替换符处理并记 warning | M | 一份 GBK 文件能正常读出中文，不抛异常 |
| FR-A-04 | diff 解析 | 解析 unified diff，识别文件段与 hunk 段，取 `@@ -a,b +c,d @@` 的新文件区间 | M | 对 `git diff` 输出解析出的 hunk 数与 `git diff --numstat` 一致 |
| FR-A-05 | 改动块切分 | 每个 hunk 切为一个或多个 `DiffUnit`，连续行合并、空行不单独成块 | M | 10 行 hunk 切成 1 块；含注释的 hunk 注释行单独标记 |
| FR-A-06 | 行号映射 | `DiffUnit.line_start/line_end` 使用新文件行号，与 `git diff` 显示的行号一致 | M | 抽查 20 个块，行号与 `git diff` 逐一对齐 |
| FR-A-07 | 大文件跳过 | 单文件 >2 MB 或 >5000 行时跳过，原因记 `too_large` | S | 造一个 3 MB 文件，出现在 skipped 列表且原因正确 |
| FR-A-08 | 二进制跳过 | 含 NUL 字节或扩展名在二进制名单内时跳过，原因记 `binary` | M | 传一张 PNG，不报错、进 skipped |
| FR-A-09 | 单文件容错 | 任一文件解析失败只影响该文件，整体继续，失败原因进 skipped | M | 目录里混一个损坏文件，其余文件照常产出块 |
| FR-A-10 | 增量模式 | `--diff <ref>` 时只处理 diff 涉及的文件与行段 | M | 改动 1 个文件 3 行，产出块数只覆盖这 3 行 |
| FR-A-11 | 全量模式 | 给路径时对全部文件产出块（用于首次接入） | M | 全量模式产出的块覆盖所有可解析行 |
| FR-A-12 | 统计回传 | 回传扫描文件数、跳过数及原因分布、块数，供报告 `counts` 使用 | S | 三个数与实际文件数、skipped 数、块数一致 |
| FR-A-13 | 输出稳定 | 同一输入两次运行，块顺序与内容完全一致（按路径字典序、行号升序） | S | 连跑 5 次，输出 SHA256 相同 |
| FR-A-14 | 注释与空行标记 | 每块标记 `is_comment` / `is_blank`，供规则跳过 | M | Python 的 `#` 行、JS 的 `//` 行标记正确 |

## 四、非功能需求

| 编号 | 对象 | 指标 | 测法 | 依据 |
|:----:|------|------|------|------|
| NFR-A-01 | 解析吞吐 | 200 个文件（约 2 万行）≤1.5 s（P95） | 开发机，连续 20 次取 P95 | 中位提交涉及 13 行，但首次接入是全量扫描，200 文件是常见仓库规模 |
| NFR-A-02 | 单文件延迟 | 2 MB 文件 ≤300 ms | 计时 20 次取中位 | 超过 2 MB 已按 FR-A-07 跳过，此处覆盖上限内最坏情况 |
| NFR-A-03 | 内存峰值 | 200 文件解析峰值 ≤200 MB | 进程 RSS 采样 | 一次只持有一个文件的文本，块按流式产出 |
| NFR-A-04 | 只读性 | 被审文件的 mtime 与内容不变 | 解析前后比对 mtime + SHA256 | 工具不得改动用户代码，这是底线 |
| NFR-A-05 | 幂等性 | 同输入两次输出完全一致 | 见 FR-A-13 | 报告要能复现，否则趋势图不可比 |
| NFR-A-06 | 编码容错 | 非法编码不抛异常，降级为替换符 | 造 GBK/UTF-8 混合文件 | 真实仓库里编码不统一是常态 |
